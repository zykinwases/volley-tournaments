# Общая идея

Приложенька для записи волейбольной статистики на основе формата из Data Volley 4.

В проект также входит модуль прогноза группового турнира: по сыгранным
матчам он оценивает силу команд, разыгрывает оставшиеся игры и показывает
вероятности итоговых мест и наиболее вероятные результаты.

# Быстрый старт

Зависимостей нет, нужен только Python 3.10+.

```bash
# Демонстрационные данные: 10 команд, 25 из 45 матчей
python main.py standings --data data/example.json

# Полный прогноз + разбор для выбранной команды
python main.py predict --data data/example.json --team "Зенит"

# Сценарии для конкретного места и выгрузка в JSON и Markdown
python main.py predict --data data/example.json --team "Зенит" --place 1 \
    --sims 200000 --json report.json --markdown report.md
```

Основная команда — `predict`. По умолчанию считается 100 000 симуляций
(около 2 секунд на 10 команд и 20 оставшихся матчей; в два круга матчей
вдвое больше, поэтому примерно вдвое дольше).

# Формат данных

JSON-файл с командами и сыгранными матчами:

```json
{
  "name": "Кубок города 2026",
  "teams": ["Зенит", "Динамо", "Спартак"],
  "rounds": 2,
  "handicap": {
    "Зенит": {"wins": 2, "points": 5}
  },
  "matches": [
    {"a": "Зенит", "b": "Динамо", "score": "3:1"},
    {"a": "Спартак", "b": "Зенит", "score": "2:3"}
  ]
}
```

* `rounds` (необязательно, по умолчанию `1`) — число кругов. `1` означает,
  что каждая пара играет один раз, `2` — дважды (дома и в гостях).
  Несыгранные матчи вычисляются автоматически с учётом числа кругов.
* `matches` содержит только сыгранные матчи. В два круга одна и та же пара
  может встретиться дважды — учитываются оба результата.
* `score` — счёт в партиях: `3:0`, `3:1`, `3:2`, `2:3`, `1:3`, `0:3`.
* `handicap` (необязательно) — стартовые победы и очки команды. Они
  прибавляются к набранным в турнире, но не считаются сыгранными матчами
  и не участвуют в соотношении партий. Допустимы обе формы записи:
  `{"wins": 2, "points": 5}` и `[2, 5]`.
* Лишние встречи пары (третья при двух кругах) и некорректные счёта
  отклоняются с понятной ошибкой.

Добавить результат в файл:

```bash
python main.py add-result --data data/example.json "Зенит" "Спартак" 3:2
```

Создать пустой турнир (гандикап указывается повторяемым флагом,
число кругов — флагом `--rounds`):

```bash
python main.py new --teams "A,B,C,D" --name "Кубок" --out data/new.json \
    --rounds 2 --handicap "A:2:5" --handicap "C:0:3"
```

Формат гандикапа: `"Команда:победы:очки"`. Указанные значения сразу
попадают в таблицу, поэтому у команды может быть больше побед, чем
сыгранных матчей, — это нормально. Если `--rounds` не указан, турнир
создаётся в один круг, как раньше.

# Как считается прогноз

## Сила команд

Считается, что каждая партия — независимое испытание Бернулли, а сила
команды — логит вероятности выиграть партию у средней команды:

```
P(команда i выигрывает партию у j) = sigmoid(r_i - r_j)
```

Рейтинги `r_i` подбираются методом максимального правдоподобия по всем
сыгранным партиям (модель Брэдли–Терри) с L2-регуляризацией. Регуляризация
не даёт рейтингам «улететь в бесконечность», если команда пока не проиграла
ни одной партии, и разумно сжимает оценки при малом числе матчей.

Из вероятности `p` выиграть партию аналитически получается распределение
счёта матча:

```
P(3:0) = p³            P(2:3) = 6·p²·(1-p)³
P(3:1) = 3·p³·(1-p)    P(1:3) = 3·p·(1-p)³
P(3:2) = 6·p³·(1-p)²   P(0:3) = (1-p)³
```

Очки и партии начисляются по регламенту: 3:0 и 3:1 — 3 очка победителю,
3:2 — 2 очка победителю и 1 проигравшему.

## Неопределённость оценок

Ковариация рейтингов берётся как обратная матрица Гессе (приближение
Лапласа). По умолчанию для каждой серии симуляций рейтинги случайно
разыгрываются из этого апостериорного распределения — так прогноз честнее
учитывает, что турнир только начался. Отключить это поведение можно флагом
`--no-uncertainty`; тогда используются точечные оценки.

## Оставшиеся матчи и число кругов

Число кругов задаётся полем `rounds` в JSON (или флагом `--rounds` при
создании турнира). В один круг каждая пара играет один раз, в два —
дважды; модель при этом не различает домашние и гостевые матчи, поэтому
обе встречи пары получают одинаковое распределение счёта. В отчёте такие
пары помечаются как `A — B (1/2)` и `A — B (2/2)`.

Каждый оставшийся матч разыгрывается по распределению счёта, после чего
таблица пересортировывается по регламенту:

1. количество побед;
2. количество очков;
3. соотношение выигранных и проигранных партий;
4. детерминированный финальный тай-брейк (больше выигранных партий, затем
   название команды) — регламент не задаёт критерий дальше соотношения,
   но для симуляции нужен однозначный порядок.

Стартовый гандикап уже включён в базовые победы и очки перед симуляцией,
поэтому сортировка и прогноз учитывают его автоматически. На количество
сыгранных матчей и соотношение партий он не влияет.

По 100 000 (или `--sims`) независимым разыгрываниям считаются:

* вероятности каждого итогового места для каждой команды;
* ожидаемые победы, очки и партии;
* наиболее вероятные полные итоговые расстановки;
* для выбранной команды — условные вероятности исходов каждого оставшегося
  матча при условии, что команда займёт заданное место.

## Почему сценарии показываются по матчам, а не одним «точным» набором

Совместный сценарий всех 20 оставшихся матчей — это одно событие из
6²⁰ возможных; в два круга матчей вдвое больше, так что вероятность ещё
меньше. Поэтому в отчёте для выбранного места приводится
таблица условных вероятностей по каждому матчу и колонка «Мода» — самый
вероятный счёт именно этого матча. Если оставшихся матчей не больше шести,
дополнительно выводятся точные наборы исходов: там их вероятности уже
осмысленны.

# Что показывает отчёт

```
Текущая таблица
Стартовый гандикап (если задан)
Оценка силы команд по сыгранным партиям
Вероятности итоговых мест, %
Ожидаемые итоговые показатели
Наиболее вероятные итоговые расстановки
Команда «...»
  Вероятности мест (1–10) и P(1–3), P(1–5)
  Сценарии для выбранного места:
    условные вероятности 3:0, 3:1, 3:2, 2:3, 1:3, 0:3
    по каждому оставшемуся матчу + мода
```

Пример условной таблицы (счёт указан для первой команды пары):

```
Матч                              3:0    3:1    3:2    2:3    1:3    0:3     Мода
Зенит — Динамо                    5.4    8.6   10.0   20.2   26.9   28.9      0:3
Зенит — Спартак                   5.0    9.2   11.5   19.8   27.4   27.0      1:3
```

Читается так: если Зенит в итоге займёт выбранное место, то в матче с
Динамо чаще всего ожидается счёт 0:3 (28.9%), а в матче со Спартаком —
1:3 (27.4%). Это не «предсказание одного точного счёта», а распределение
исходов, совместимое с итоговым местом.

# Флаги `predict`

| Флаг | Назначение |
| --- | --- |
| `--data PATH` | файл турнира (по умолчанию `data/example.json`) |
| `--team NAME` | разобрать вероятности мест и сценарии для команды |
| `--place N` | целевое место для сценариев (по умолчанию самое вероятное) |
| `--sims N` | число симуляций (по умолчанию 100000) |
| `--seed N` | зерно генератора для воспроизводимости |
| `--prior X` | сила регуляризации рейтингов (по умолчанию 1.0) |
| `--no-uncertainty` | считать по точечным оценкам силы |
| `--top N` | сколько расстановок/сценариев показывать |
| `--json PATH` | сохранить структурированный отчёт |
| `--markdown PATH`, `--md PATH` | сохранить отчёт в Markdown |

Все таблицы отчёта доступны в трёх видах: обычный текст в консоли,
JSON (`--json`) для дальнейшей обработки и Markdown (`--markdown`) для
вставки в вики, GitLab/GitHub или мессенджер. Родительские каталоги
создаются автоматически, файл пишется в UTF-8.

# Ограничения

* Модель не знает о травмах, мотивации, домашнем преимуществе и ротации
  состава — только о счёте сыгранных партий.
* Предполагается постоянная вероятность выиграть партию в течение матча;
  реальные матчи могут иметь «качели» и психологический фактор пятой партии.
* При малом числе сыгранных матчей и сильной регуляризации оценки
  сближаются; неопределённость при этом широкая, что видно по прогнозу.
* Тай-брейк дальше соотношения партий в регламенте не задан; используется
  детерминированное правило, описанное выше.
